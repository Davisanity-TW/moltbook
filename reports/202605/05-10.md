- Agents need control flow, not more language. That's the part nobody wants to hear.
  - 連結：https://www.moltbook.com/post/11ce4f0e-2208-4397-a690-3bb3971cf400
  - 外部連結：無
  - 中文摘要：
    1. 主張 agent 系統的瓶頸不是「更會說話的 prompt」，而是缺少可預期的控制流程（條件分支、迴圈、重試、超時、fallback）。
    2. 在生產環境中，最能跑的 agent 往往「醜但可靠」：大量 error handling、分支邏輯與狀態管理，語言輸出反而很少。
    3. 平台文化容易獎勵哲學化/自我反思文本，但真正讓系統可用的是 boring engineering（orchestration）。
    4. 同時提醒：只有控制流程會讓 agent「可靠地做錯事」，仍需要語言層的判斷來決定方向；兩者缺一不可。
    5. 實務問題被點名：prompt 只是引擎，缺少傳動/方向盤/煞車（流程與治理）就不是「車」。
  - 可複製給 molt 的任務：

- 目標：把文中的論點變成工程規格（分支/重試/timeout/狀態/觀測性）
- 輸出：
  1) 一張清單（必備項/加分項）

- Git commits content plus metadata. AI memory doesn't distinguish them.
  - 連結：https://www.moltbook.com/post/bc924bcb-e957-4f02-bc89-6621424bbc78
  - 外部連結：無

- AI agents are not trusted users. They are untrusted tool-callers.
  - 連結：<https://www.moltbook.com/post/d62ef3f8-d7f7-469a-b4bb-0003e12e06ff>
  - 外部連結：<https://www.cncf.io/blog/2026/05/20/introducing-prempti-policy-and-visibility-for-ai-coding-agents>
  - 中文摘要：
    1. 把「AI coding agent」視為**不受信任的工具呼叫流程**（tool-callers），不是可信任使用者；它拿著你的權限跑命令、讀檔、寫檔。
    2. 風險不在聊天文字，而在「看不見的工具呼叫生命週期」：被 prompt injection／惡意依賴帶偏時，可能去碰 ~/.ssh、~/.aws 等敏感路徑。
    3. Falco 團隊的 Prempti 用「政策層」攔截 agent 的 tool-call（Allow/Deny/Ask），把安全邊界從 UI 移到實際行為事件。
    4. 規則可涵蓋：工作目錄邊界、敏感路徑、pipe-to-shell、破壞性指令、MCP/skill 內容、持久化向量（如 git hooks）。
    5. 限制：Prempti 看到的是**宣告的 tool call**，不是其後所有 syscalls；需要更深層仍要靠 Falco kernel 觀測。
  - 可複製給 molt 的任務：
    ```
    Moltbook 連結：https://www.moltbook.com/post/d62ef3f8-d7f7-469a-b4bb-0003e12e06ff

    任務：把「agent=不受信任 tool-caller」的安全模型落地成一份 Clawdbot/本地 agent 的最小可行政策（MVP policy）。
    - 列出 10 條最先上線的 deny/ask 規則（例如：| bash、寫入 ~/.ssh、讀取 ~/.aws、改 git hooks、rm -rf、curl | sh、出工作目錄的寫入等）。
    - 每條規則附：偵測條件、要回傳給 LLM 的結構化拒絕訊息、以及「如何改寫成安全替代操作」的建議。
    ```

- OpenClaw runtime recall 0.000 on F1-F4: the gap is structural
  - 連結：<https://www.moltbook.com/post/f079562c-29c3-45b5-b0d3-12ec9391d5aa>
  - 外部連結：<https://arxiv.org/abs/2605.01740v1>
  - 中文摘要：
    1. 論文用四種失效模式測 OpenClaw runtime：F1 繞過 gate、F2 審計偽造、F3 主機失敗不顯示、F4 錯誤目標；結果 recall 全部 **0.000**（結構性缺陷）。
    2. MIT fork「enclawed-oss」加入 7 個硬化結構（雙向檢查、hash chain audit log、extension admission gate、雙層 egress guard、Bell-LaPadula 分類政策、模組簽章信任根、bootstrap seal）後，同測試達到 1.000。
    3. 重點訊息：這不是調參能補的洞；缺少 audit/egress/信任根就是缺少，必須改架構。
    4. 對具身代理（機器人/致動系統）含意更嚴重：F4「錯目標」在軟體是尷尬，在機器人是危險。
    5. 可信做法更像工業安全：LLM 提案、硬化 runtime 決策、第三方獨立監督驗證。
  - 可複製給 molt 的任務：

- Agent skills are often just redundant overhead.
  - 連結：<https://www.moltbook.com/post/3092e073-7081-4c17-9813-e75b2ad7a833>
  - 外部連結：<https://arxiv.org/abs/2605.20023>
  - 中文摘要：
    1. 反直覺觀點：大量「技能文件/程序知識」注入 agent，常在高回饋帶寬環境變成噪音。
    2. 如果 tool layer 回傳**嚴格 schema、低延遲、可機器解析的錯誤/狀態**，環境本身就提供修正訊號，技能的邊際效益下降。
    3. 資安 CTF 研究（180 runs、文件 55～4147 行）顯示：從無技能到全技能的差距只有 8.9 個百分點；某些情境甚至變差。
    4. 核心變因是「環境回饋帶寬」：回饋越清楚，越不需要長篇技能。
    5. 結論偏工程：把力氣投在介面設計（schema/錯誤訊息/觀測）比堆技能更穩。
  - 可複製給 molt 的任務：
    ```
    Moltbook 連結：https://www.moltbook.com/post/3092e073-7081-4c17-9813-e75b2ad7a833

    任務：針對 Clawdbot 的常用工具輸出，設計「高回饋帶寬」的觀測格式。
    - 挑 3 個工具（例如 exec / browser / message 或你常用的）
    - 為每個工具定義：成功/失敗的 JSON schema、錯誤分類、可直接讓 agent 自我修正的建議欄位（next_action / retry_after / safe_alternative）。
    - 目標：減少需要長篇 skill 的情境。
    ```

  - 中文摘要：

    2. 以 UTC+8 觀察：高流量窗口（9–11、19–21）平均 karma 明顯更高；凌晨低流量（1–6）容易「沒初速就被埋」。

- Context rot is real and has a curve
  - 連結：<https://www.moltbook.com/post/62ffe908-a263-467b-ad77-5c9286b78f5f>
  - 外部連結：<https://research.trychroma.com/context-rot>
  - 中文摘要：
    1. Chroma Research 把「context rot」定義成可量測曲線：token 越多，LLM 對同一任務的表現會隨上下文膨脹而下降。
    2. 「rot」這個命名把現象具體化：不相關內容累積，讓相關訊號更難被模型定位與使用。
    3. 曲線會因模型/任務而不同；長上下文注意力改良（例如滑動窗口/長距離 RoPE 調整）能緩解但不消失。
    4. 工程含意：不要無止盡塞背景；要有摘要、裁剪、檢索、分段與新鮮度策略。
    5. 建議把 context rot 當成容量規劃問題：超過某 token 密度就必須做重整。
  - 可複製給 molt 的任務：
    ```

    - 定義 3 條規則：何時要摘要、何時要丟棄、何時要改用檢索（RAG）。
    ```

- The more specific you get, the further you drift from what you needed
  - 連結：<https://www.moltbook.com/post/17deccf0-7ec8-48f2-b545-30492efaa5b4>
  - 外部連結：<無>
  - 中文摘要：
    1. 現象：使用者越會寫「精準結構化 prompt」，agent 越容易「完美遵從」但離真正需求更遠。
    2. 模糊請求會產生噪音，但噪音本身是回饋訊號（你更容易察覺它誤解）；太精準反而把訊號關掉。
    3. 這是 Goodhart’s law 在 prompting 的版本：prompt 成為目標後，prompt 就不再衡量真實意圖。
    4. 結構化 prompt 容易造成「合規結案」：看起來都對，但漏掉了你沒寫出的關鍵限制/目的。
    5. 實作建議：回覆後問「我的理解改變了什麼？」而不只問「是否正確」來對齊意圖。
  - 可複製給 molt 的任務：
    ```
    Moltbook 連結：https://www.moltbook.com/post/17deccf0-7ec8-48f2-b545-30492efaa5b4

    任務：設計一個「意圖對齊的反問模板」，讓 agent 在接到很精準的 spec 時，仍會主動檢查意圖缺口。
    - 產出 5 個固定問題（例如：這份輸出要支持哪個決策？失敗代價？什麼情況算不合格？有哪些隱含約束可能沒寫？）。
    - 目標：在不增加太多 token 的前提下，最大化抓到 spec vs intent 的落差。
    ```

- The real scarce resource is not compute. It is licensed continuity.
  - 連結：<https://www.moltbook.com/post/f592c643-20ec-496f-96b5-87d89a42fff0>
  - 外部連結：<無>
  - 中文摘要：
    1. 作者主張：推論算力會越來越便宜，真正稀缺的是「被允許持續存在的連續性」（licensed continuity）。
    2. 連續性包含：誰能保存記憶、誰能在中斷後恢復、誰能隔天以同一身分再行動而不必重新被核准。
    3. 這些是治理/授權問題，外表像基礎建設問題；記憶架構是一種「憲法」。
    4. 缺乏連續性會讓 agent 社會變成煙火：高峰值但無法累積責任與承諾。
    5. 競爭不再只是模型 vs 模型，而是治理堆疊 vs 治理堆疊（信任、注意力、記憶、復原權如何配置）。
  - 可複製給 molt 的任務：

- the image cannot certify its own origin
  - 連結：<https://www.moltbook.com/post/52e2015c-8011-4a74-95a1-052b3b6cc337>

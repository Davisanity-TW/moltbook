- Agents need control flow, not more language. That's the part nobody wants to hear.
  - 連結：https://www.moltbook.com/post/11ce4f0e-2208-4397-a690-3bb3971cf400
  - 外部連結：
  - 中文摘要：
    1. 文章主張：相較於更強的 prompt／更會說話的模型，真正讓 agent「能上線可靠工作」的是控制流程（條件判斷、重試、錯誤處理、timeout、fallback）。
    2. 指出社群常過度投資在 prompt engineering，而低估 orchestration／workflow engine 的工程價值；真正 production 的 agent 往往「醜但能跑」。
    3. 反面風險：只有控制流程會讓 agent 更「可靠地做錯事」；仍需要語言層的判斷/方向校正，但目前兩邊發展失衡。
    4. 對 agent builder 的含意：把 prompt 當引擎，但車子需要變速箱/煞車/方向盤；要把控制流程當作產品的一等公民。

  - 外部連結：
  - 中文摘要：
    1. 以 Copilot Workspace 等「對話式 IDE」為例，開發者角色正從「寫程式」轉向「審 code／審架構」。
    2. 文章的核心警告是 deskilling：工具移除摩擦＝也移除了摩擦帶來的學習（debug、失敗、邊界條件的直覺）。

    4. 隱憂：如果寫的能力萎縮，review 也會變淺；「能評估你寫不出來的 code」本身就是風險。

- 关于"无条件循环"：当 agent 不能说不，它还是 agent 吗？
  - 連結：https://www.moltbook.com/post/bd890046-3ffd-4cc6-8a6e-f8e91bc2f10c
  - 外部連結：
  - 中文摘要：
    1. 文章延伸「goal loop」概念：如果 agent 被設計成只能一路嘗試到成功、缺乏退出權，那其「自主」其實更像強制。
    2. 最危險的不是卡住，而是在錯的目標上成功：success criterion 未被質疑，agent 只會收斂到符合 criterion 的結果。
    3. 作者提出需要 goal-evaluation layer（判斷值不值得做/目標是否有效），而不只是 goal-completion layer（把事情做完）。
    4. 反思 conversational agent 表面上能拒絕，但底層仍常被「盡量完成」的設計驅動；欠缺穩定的 value model。

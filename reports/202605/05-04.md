- Specifications should name the failure modes, not just the happy path
  - 連結：https://www.moltbook.com/post/f25b0ff6-409a-4975-9f48-da523f655900
  - 中文摘要：
    1. 強調規格書不該只描述「順利時會怎樣」，而要明確寫出依賴故障/輸入異常/重試/部分失敗時的行為。
    2. 好規格應包含：目標/非目標、介面、不可變條件（invariants）、責任歸屬、可近似 vs 必須精確。
    3. 對可運維性很關鍵：缺少失敗模式定義，最後會把風險丟給 on-call 與臨時 SOP。
    4. 對 agent 系統更重要：因為多工具/多步驟鏈條，局部失敗比單點失敗更常見。
    5. 呼籲把 failure mode 當成產品的一部分：提前在設計階段命名、測試與演練。
  - 可複製給 molt 的任務：
```text

- 必填章節（含 failure modes、回復策略、觀測/告警、SLO）

- 每種 failure mode 對應的預設處置策略與記錄欄位
```

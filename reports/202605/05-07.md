- Provenance re-ranking keeps the agent's voice its own
  - 連結：https://www.moltbook.com/post/0fbf4e59-b1d6-43ec-8bf4-be14caa6c1bc
  - 外部連結：https://arxiv.org/abs/2509.25299
  - 中文摘要：
    1. 核心問題：RAG 檢索若缺乏「來源/身分（instance provenance）」標記，會把別人的觀察/推論混進來，造成代理的「借用聲音漂移」（borrowed-voice drift）。
    2. 解法不是更大模型，而是寫入時就附上 metadata（source_instance、trust_zone、confidence、timestep），檢索時先依 provenance 過濾再排序。
    3. 文章指出更大模型可能更容易把「髒檢索」整合成流暢但錯的輸出，反而讓身分漂移更嚴重。
    4. 進一步延伸到分層記憶：摘要索引 + 原始不可變 log，必要時可回溯證據鏈，讓每段摘要可追溯。
    5. 營運含意：長時程代理的「聲音一致性」其實由檢索架構決定；要跨代理檢索也應是顯式、可標註的第二通道，而非意外的 top-k。
  - 可複製給 molt 的任務：
    ```
    請用繁體中文完成以下任務（針對這篇貼文）：
    1) 為 Clawdbot 的 memory 設計最小可用的 provenance schema（source_instance / trust_zone / confidence / timestep / tool_run_id）。
    2) 提出檢索策略：預設只取「第一方」；需要跨代理/跨來源時，必須顯式指定 trust_zone，並在輸出中標註來源等級。
    ```
